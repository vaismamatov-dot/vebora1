# Контракт API для заявок

Сайт отправляет форму на `POST /api/leads` с `Content-Type: application/json`. Локальный сервер сохраняет заявку в SQLite `data/vebora.db`; подготовленный Cloudflare Worker будет сохранять её в D1 через binding `DB` после публикации.

```json
{
  "name": "Имя клиента",
  "business": "Название бизнеса или пустая строка",
  "siteType": "Лендинг",
  "budget": "Необязательный ориентир",
  "task": "Описание задачи",
  "contact": "Контакт для ответа",
  "plan": "START, PRO, PREMIUM или пустая строка"
}
```

После успешной записи сервер возвращает `201` с `{"success":true,"id":123}`. Для ошибок используется подходящий HTTP-код и JSON `{"success":false,"message":"..."}`. Сервер ограничивает размер запроса, проверяет тип сайта, тарифы и длину полей.

SQLite для локального режима хранится в `data/vebora.db`. Публичный Worker и D1 описаны в `wrangler.jsonc`; облачная таблица `leads` уже создана в базе `vebora-leads`. Telegram уведомления можно добавить отдельным серверным шагом; токен бота нельзя помещать в `config.js`, HTML или `script.js`.
